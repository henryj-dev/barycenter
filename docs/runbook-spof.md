# SPOF 런북 — 데이터 플레인은 한 대다

v1 데이터 플레인은 **단일 장애점**이다. 자동 페일오버는 없다. 콜드 스탠바이가
있고, 트래픽을 옮기는 것은 DNS 또는 상위 L4 다. 멀티 노드 HA 가 아니다.

숫자는 **v1 운영 정책**이다. [`docs/adr-spof.md`](./adr-spof.md) 가 확정한다.
랩에서 잰 SLA 가 아니다. 페일오버는 수동이다.

## 운영 정책

| 항목 | 정책 | 비고 |
|---|---|---|
| RTO (DP 호스트 손실 → 서비스 복구) | ≤ 15분 | 수동 페일오버 |
| RPO (설정 손실) | 0 | 정본은 PostgreSQL. 아티팩트는 재생성 |
| PG 손실 시 RPO | ≤ 5분 | PITR/스트리밍이 있을 때 |

## 백업 세 종

1. `bary backup` — spec-only 매니페스트 + head 리비전. 시크릿 바이트 없음.
2. PostgreSQL 덤프 — 정본.
3. SecretStore 디렉터리 (`BARY_SECRETS`) — 인증서 자료.

복구 리허설: 백업을 받아 `bary restore` 로 head 를 되돌린 뒤 `bary apply --plan` 으로
트래픽에 건다. restore 는 apply 가 아니다.

## 수동 페일오버

1. 스탠바이가 **동시에 listen 하지 않게** 한다. 포트 탈취를 막는다.
2. 같은 세대 아티팩트가 스탠바이에 있는지 본다.
3. DNS 또는 상위 L4 를 스탠바이로 돌린다. **자동이 아니다.**
4. 옛 호스트는 내린다.

리더 선출은 PG advisory lock 이다. 스탠바이 컨트롤 플레인은 읽기만 답하고
쓰기는 503 `not_leader` 다.
