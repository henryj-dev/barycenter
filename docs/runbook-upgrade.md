# 업그레이드 런북 — 다시 깐다

**업데이트 명령은 따로 없다.** 새 코드를 받아 `deploy/install.sh` 를 그대로 다시 돌리는
것이 업데이트다. 그래서 이 문서가 답하는 것은 "어떻게 올리나" 가 아니라 **"다시 돌리면
무엇이 안 부서지나"** 다.

전제는 §11.3 의 v1 권장 배포다 — 전용 VM 한 대, 엔진과 데몬이 한 유닛.

## 절차

```sh
cd /path/to/barycenter
git fetch origin && git checkout <태그 또는 커밋>

sudo deploy/install.sh --dsn 'postgres:///bary?host=/run/postgresql'
```

처음에 `--with-postgres` 로 깔았어도 **다시 돌릴 때는 `--dsn`** 을 준다. PG 는 이미 서
있고, 그 옵션은 "이 호스트에 PostgreSQL 을 설치하라" 는 뜻이라 다시 줄 이유가 없다.
DSN 값은 `$PREFIX/env` 의 `BARY_DSN` 에 있다.

`--tls-cert`·`--listen`·`--user` 처럼 **이 스크립트가 정하는 값들은 다시 준다.** 관리
키는 매번 다시 쓰이므로, 안 주면 기본값으로 돌아간다.

`--env` 로 준 것들은 **다시 안 줘도 된다** — 이어 간다(아래).

## 재실행이 안 부수는 것

| | 어떻게 |
|---|---|
| `$PREFIX/tokens.json` | **그대로 둔다.** 운영자가 손으로 더한 토큰까지 전부 |
| `$PREFIX/env` 의 관리 밖 줄 | **이어 간다.** `BARY_SECRET_KEK` 을 포함해서 |
| PostgreSQL 안의 모든 것 | 안 건드린다. 마이그레이션은 데몬이 기동에서 올린다 |
| 활성 세대 | 재기동이 되돌리지 않는다 — 부트스트랩은 데몬이 쓴다 (§6.5-1) |

**토큰을 새로 발급하지 않는 이유**는 그것이 업데이트가 할 일이 아니어서다. 새로 발급하면
그 API 를 부르던 것 — 운영자의 `BARY_TOKEN`, CI, 배포 스크립트 — 이 전부 그 자리에서
끊긴다. 그리고 끊긴 사실은 **다음에 그것을 돌릴 때** 드러난다.

**KEK 을 이어 가는 이유**는 더 무겁다. `BARY_SECRET_BACKEND=pg` 에서 `BARY_SECRET_KEK`
을 잃으면 인증서 자료를 **영영 못 연다**([`runbook-spof.md`](./runbook-spof.md)). 덤프에
있는 것은 암호문뿐이고 그것이 이 드라이버의 요점이다. 업데이트가 그걸 조용히 할 수는 없다.

## 재실행이 바꾸는 것

- `$APP_DIR` 의 `dist`·`node_modules`·`gui/build`·`drivers` — 통째로 새것으로 바뀐다
- 유닛 파일 — 다시 쓰이고 `restart` 한다
- `$PREFIX/env` 의 **관리 키** — 다시 계산해 쓴다 (`--help` 의 목록)
- 패키지 — `--skip-packages` 를 안 주면 확인·설치한다

즉 **짧은 다운타임이 있다.** 데몬과 엔진이 한 유닛이라 `restart` 동안 트래픽이 끊긴다.
무중단이 필요하면 이 배포 형태가 아니라 SPOF 런북의 페일오버 절차를 쓴다.

## 뒤집는 문

| 플래그 | 언제 |
|---|---|
| `--rotate-token` | 토큰을 잃었거나 유출됐다. `ops` 만 갈아 끼우고 다른 토큰은 남긴다. 평문은 그때 한 번만 보인다 |
| `--reset-env` | env 를 처음처럼 다시 쓴다. **관리 밖 줄이 전부 사라진다** — KEK 을 쓰고 있다면 `--env` 로 다시 줘야 한다 |

## 확인

설치가 스스로 `/healthz` → `/readyz` 까지 보고 끝난다. 그 다음 한 줄:

```sh
BARY_URL=http://127.0.0.1:8088 BARY_TOKEN=<쓰던 토큰> \
  node /opt/barycenter/dist/bin/bary.js status
```

⚠️ **토큰을 보존한 실행은 `bary status` 를 스스로 못 잰다** — 해시만 있고 평문이 없다.
설치는 대신 *"인증 없는 요청에 401 이 오는가"* 를 재고 그렇게 말한다. 그것이 서는 것은
**토큰 평면이 살아 있다**이지 *"당신의 토큰이 맞다"* 가 아니다. 후자는 위 한 줄로
운영자가 확인한다.

## 되돌리기

옛 커밋으로 `git checkout` 하고 같은 명령을 다시 돌린다. 산출물은 통째로 바뀌므로
코드는 그것으로 돌아간다.

⚠️ **DB 스키마는 안 돌아간다.** 마이그레이션은 앞으로만 간다 — 새 버전이 올린 스키마
위에서 옛 코드가 도는지는 보장하지 않는다. 스키마가 바뀐 버전을 되돌리려면 PG 덤프에서
복구한다(RPO 는 SPOF 런북의 표를 따른다).

## 무엇이 이것을 지키나

`tests/install/run.sh` 의 debian 판이 **실물 컨테이너에서 두 번 깐다.** 두 번째 설치
뒤에 보는 것:

- 첫 설치의 토큰이 그대로 통하는가
- `BARY_SECRET_KEK` 이 env 에 남았는가 (재설치 명령에는 안 줬다)
- env 에 같은 키가 두 줄 들어가지 않았는가

`tests/unit/install-script.test.ts` 는 `carry_env_lines` 를 **스크립트에서 꺼내 직접
돌린다** — 규칙을 테스트가 다시 적으면 그 사본이 원본과 갈라지는 날 초록인 채로 아무것도
안 지킨다.
