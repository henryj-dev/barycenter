# ADR — 호스트 리스너: 한 소켓을 서비스마다 나눠 쓴다

- 상태: 채택 (2026-10-31)
- 범위: HTTP · HTTPS 리스너. TCP · UDP · TLS 패스스루는 그대로다.

## 맥락

지금 리스너는 **소켓(주소:포트) 하나**다. 호스트 이름은 그 안의 HTTP 라우트가 정한다. 그래서 `0.0.0.0:443` 을
쓰는 리스너는 하나뿐이고, 사이트마다 인증서 · 출발지 제한 · 기본 동작 · 타임아웃 · 헤더를 따로 둘 수 없다.

운영자가 원하는 단위는 **서비스**다. 서비스 하나가 nginx 의 `server` 블록 하나다.

```
http   { server { listen 443 ssl; server_name a.example.com; … } }   ← 서비스 A
http   { server { listen 443 ssl; server_name b.example.com; … } }   ← 서비스 B (같은 소켓)
stream { server { listen 5432; … } }                                 ← 서비스 C
```

nginx 는 이 모양을 그대로 받는다. 막는 것은 우리 모델과 검증기다.

## 결정

1. **HTTP · HTTPS 리스너에 `hosts` 를 둔다** (`server_name`). 있으면 「호스트 리스너」 다.
   - 호스트마다 `server { listen …; server_name <호스트>; … }` 를 낸다.
   - 그 server 의 기본(`location /`)은 리스너의 `defaultAction` 이다. 리스너의 라우트는 그 안에서 경로로 나눈다.
   - 인증서(기본 인증서 · SNI 바인딩), 출발지 제한, 한계값, 헤더, 레이트리밋은 리스너의 것이다.
2. **같은 소켓을 여러 리스너가 함께 쓸 수 있다.** 조건:
   - 모두 HTTP 이거나 모두 HTTPS 다. 평문과 TLS 를 한 포트에 섞지 않는다.
   - 바인드가 같다(정규형).
   - 와일드카드와 특정 주소는 **소켓을 함께 쓰지 않고 나눠 쓴다** (2026-10-31 개정). 같은 nginx 컨텍스트(http ↔ http,
     stream ↔ stream)면 충돌이 아니다. nginx 는 와일드카드 소켓 하나만 열고, 도착 주소로 server 를 고른다.
     **특정 주소로 온 요청은 특정 주소 리스너가 받는다.** 나머지 주소는 와일드카드가 받는다. 예: `0.0.0.0:80`
     (내부 리다이렉트)과 `64.176.226.52:80`(공인 IP 의 ACME). 컨텍스트가 다르면(http ↔ stream) 각자 bind() 해서
     기동이 실패하므로 충돌이다. UDP 도 충돌이다(프리셋이 `reuseport` 로 주소마다 bind() 한다).
     실측: `tests/golden/bind-precedence.test.ts`.
     처음 결정은 「어느 server 가 받는지가 주소에 따라 바뀐다」 를 이유로 막았다. 그 동작이 곧 특정 주소 우선이고,
     결과는 결정적이다.
   - 소켓 단위 옵션이 같다: PROXY protocol 수신(`listen … proxy_protocol`).
   - 그 소켓에서 **호스트 이름이 겹치지 않는다** — 호스트 리스너의 `hosts` 와 호스트 없는 리스너의 라우트 호스트를
     모두 합쳐 본다. 겹치면 nginx 는 경고만 내고 먼저 나온 server 에 준다(E36). 조용한 오동작이다.
   - 호스트 없는 리스너는 그 소켓에 **하나까지**다. 그것이 그 소켓의 `default_server` 다(지금 동작).
3. **호스트 없는 리스너가 없는 소켓의 `default_server` 는 렌더러가 만든다.** 어느 호스트에도 맞지 않는 요청을 끊는다.
   - HTTP: `return 444`. ACME 확인 경로는 남긴다.
   - HTTPS: `ssl_reject_handshake on` — TLS 핸드셰이크에서 끊는다. **어느 서비스의 인증서도 내주지 않는다**(S17:
     default 가 없으면 첫 블록의 인증서가 나가 테넌트 사이로 샌다). nginx 1.19.4+ 가 필요하다. 엔진이 못 하면
     검증기가 그 소켓에 호스트 없는 리스너를 요구한다.
4. **TCP · UDP 는 지금처럼 포트마다 리스너 하나다.** 호스트 이름이 없어 nginx 가 가를 수 없다. TLS 패스스루는
   지금처럼 SNI 라우트로 나눈다.
5. **호스트 리스너의 라우트**는 그 리스너의 호스트 안에서만 산다 — 라우트의 호스트는 리스너의 `hosts` 중 하나여야 한다.

## 바뀌지 않는 것

- `hosts` 가 없는 리스너는 지금과 같은 렌더를 낸다(바이트까지 같다). 기존 배포의 다음 apply 가 세대 전환을 하지 않는다.
- 소켓 충돌 규칙은 호스트 리스너끼리의 「같은 바인드 · 같은 프로토콜 · 호스트 안 겹침」 만 풀린다. 나머지는 그대로다.

## 결과

- 「서비스 하나 = 리스너 하나 = server 블록」 이 된다. GUI 의 리스너 목록이 서비스 목록이 된다.
- 같은 443 에서 서비스마다 인증서 · 출발지 제한 · 타임아웃 · 헤더를 따로 둔다.
- 대가: 같은 소켓의 리스너들은 PROXY 수신 같은 소켓 단위 옵션을 맞춰야 한다. 검증기가 어긋난 것을 이름으로 말한다.
