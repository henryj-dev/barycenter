## 2. 보안

이 시스템의 신뢰 경계는 `write` 스코프다. S-01·S-02·S-03 은 그 경계를 넘는다 — 설정을
고칠 권한이 호스트 파일시스템 쓰기, 클라이언트 IP 위조, 권한 상승으로 번진다.

### S-01 · Critical — 인증서 `key` 가 파일 경로에 그대로 들어간다 (재현함)

리소스 `key` 에는 **어떤 형식 검증도 없다.** 해독기는 문자열이면 통과시키고, DB 는
`text NOT NULL UNIQUE` 일 뿐 패턴 CHECK 이 없다. 그런데 인증서 key 는
`certs/<key>/<version>/privkey.pem` 이라는 **파일 경로**가 되고,
`materializeGeneration` 이 `join(tmp, rel)` 로 그대로 쓴다. `join` 은 `..` 을
정규화하므로 세대 디렉토리를 벗어난다.

```
$ key = '../../../../pwned'
certPaths →  certs/../../../../pwned/aaaa…/fullchain.pem
쓰인 곳   →  /tmp/pwned/aaaa…/fullchain.pem   (prefix 밖)
verifyGeneration →  PASSED
```

`openSync(path,'wx')` 라 기존 파일을 덮지는 못하지만, 데몬 uid(컨테이너에서 **root**)로
새 파일을 임의 위치에 만들 수 있다. 내용은 업로드한 PEM 이고, `inspectMaterial` 은 PEM
블록이 *어딘가* 있기만 하면 되므로 앞뒤에 임의 텍스트를 붙일 수 있다. cron 조각·nginx
include·유닛 파일이 사정권이다. `verifyGeneration` 도 이탈 경로를 통과시킨다.

- 위치 — `src/dp/secrets.ts:250-251` · `src/conf/render.ts:522` · `src/dp/materialize.ts:167` · `src/store/config-store.ts:492`
- 고치는 법 — 해독기에 리소스 key 문법을 넣는다(`^[A-Za-z0-9][A-Za-z0-9._-]{0,62}$` 정도,
  SecretStore 가 이미 이름에 쓰는 것과 같은 규칙). DB CHECK 도 같이 건다. 추가로
  `materializeGeneration` 이 `rel` 이 정규화 후에도 tmp 안에 있는지 확인하고,
  `verifyGeneration` 은 `..` 을 담은 manifest 항목을 거부한다. 방어는 두 겹이어야 한다.

### S-02 · High — https 리스너의 PROXY 수신에 `real_ip_header` 가 안 나간다 (재현함)

`realipNodes` 가 `listener.protocol === 'http'` 일 때만 `real_ip_header proxy_protocol;`
을 낸다. 그런데 **https 도 http 컨텍스트**다. 결과적으로 https 리스너에는
`set_real_ip_from` 만 나가고, nginx 의 기본 `real_ip_header` 는 `X-Real-IP` 다.

```nginx
server {
    listen 443 proxy_protocol ssl default_server;
    set_real_ip_from 10.0.0.0/8;
    ← real_ip_header 가 없다
    …
```

그래서 **PROXY 헤더의 주소가 `$remote_addr` 에 반영되지 않고**, 대신 신뢰 대역 안의
앞단이 넘긴 `X-Real-IP` *HTTP 헤더*가 반영된다. 앞단이 그 헤더를 정리하지 않으면
클라이언트가 자기 IP 를 정한다 — `ip_hash` peer 선택, `X-Forwarded-For`, 백엔드의 IP 기반
ACL 이 전부 그 값을 믿는다. 모듈 주석이 막았다고 적어 둔 바로 그 상태다.

같은 `'http'` vs *http 컨텍스트* 혼동이 검증기에도 있다. `validateModel` 은 https + PROXY
조합에 `stream_realip` capability 를 요구하는데, https 는 stream 이 아니다. OpenResty 에는
`stream_realip` 이 없으므로 **https 리스너의 PROXY 수신이 아예 저장 불가**다.

- 위치 — `src/conf/render.ts:494` · `src/validate/model.ts:281`
- 고치는 법 — 조건을 `protocol === 'http' || protocol === 'https'` 로 넓힌다. 검증기 쪽은
  반대로 https 를 제외 목록에 넣고, https 에는 `http_realip_module` 유무를 본다.

### S-03 · High — 모르는 role 이 admin 이 된다

`scopesOfRole` 은 `auditor` 와 `operator` 만 분기하고 **나머지 전부를 admin 으로 떨군다.**
그리고 `loadTokens()` 는 JSON 을 `as TokenSpec[]` 로 캐스팅할 뿐 `role` 값을 검증하지 않는다.

```ts
if (role === 'auditor')  return ['read'];
if (role === 'operator') return ['read','write'];
return ['read','write','apply','admin'];  // ← 그 외 전부
```

`BARY_TOKENS` 에 `"role":"operater"` 라고 오타를 내면 그 토큰이 `/restore`·`/apply`·
`/recover` 를 포함한 전권을 얻는다. 기동 로그에도 안 보인다. OIDC 경로는 `isRole` 가드가
있어 안전하지만 설정 경로가 열려 있다.

- 위치 — `src/api/auth.ts:28-32` · `src/bin/barycenterd.ts:66-75`
- 고치는 법 — `scopesOfRole` 이 `admin` 만 전권을 주고 나머지는 던지게 한다(fail closed).
  `loadTokens` 에 `TokenSpec` 해독기를 붙여 `scopes`·`role` 값을 화이트리스트로 검사한다.
  이 저장소가 모델에 대해 이미 세운 규칙을 설정 파일에도 적용하는 것뿐이다.

### S-04 · High — `checkEngineConstraints` 를 아무도 부르지 않는다

`src/validate/engine-constraints.ts` 는 *"PROXY 수신 + 송신을 함께 켜면 백엔드가 LB 주소를
받는다 … 그래서 저장 자체를 막는다"* 를 구현하고, 단위 테스트 8개가 전부 초록이다. 그런데
**프로덕션 호출자가 0개**다. `render.ts:27` 과 `validate/model.ts:18` 은 같은 파일에서
`poolsReachedBy` 만 import 하는데 그것도 **어디서도 쓰이지 않는다.**

즉 그 체인 조합은 지금 **그대로 저장되고 그대로 렌더된다.** 테스트가 초록이라 이 상태는
CI 에서 보이지 않는다.

- 위치 — `src/validate/engine-constraints.ts` (호출자 없음) · `tests/unit/engine-constraints.test.ts` (초록)
- 고치는 법 — `validateModel` 안으로 접어 넣거나 `ConfigStore` 가 capability 와 함께
  부르게 한다. 그리고 *"호출자 없는 export 는 실패"* 를 적합성 테스트로 못 박으면 이
  부류가 다시 안 생긴다.

### S-05 · Medium — 제어 API 에 TLS 가 없다

`createApi` 는 `node:http` 의 `createServer` 뿐이고 코드 어디에도 `node:https` 가 없다.
그런데 이 API 로 `POST /certificates/material` 이 **개인키 PEM 을 본문에 담아** 보내고,
Bearer 토큰도 매 요청에 실린다.

기본 바인드는 `127.0.0.1:8088` 이지만 **배포 이미지의 기본값은 `BARY_LISTEN=0.0.0.0:8088`**
이다. compose 가 루프백으로 퍼블리시해 가려 주고 있을 뿐, k8s 나 `docker run -p 8088:8088`
로 띄우면 그대로 노출된다.

- 위치 — `src/api/server.ts:654` · `deploy/Dockerfile` (`ENV BARY_LISTEN=0.0.0.0:8088`)
- 고치는 법 — `BARY_TLS_CERT`/`BARY_TLS_KEY` 로 `https.createServer` 를 열고, TLS 없이
  루프백 밖에 바인드하면 기동을 거부한다. 이미지 기본값은 `127.0.0.1:8088` 로 되돌린다.

### S-06 · Medium — OIDC 가 사실상 HS256 전용

`OidcSettings.key` 는 `string | KeyObject` 인데, 데몬은 `env('BARY_OIDC_KEY')` 로
**문자열만** 만들 수 있다. `verifyJwtSig` 는 RS256 일 때 `typeof key === 'string'` 이면
즉시 `false` 다. alg 혼동은 이 구조 덕분에 막히지만, 동시에 **RS256 경로가 프로덕션에서
도달 불가**가 된다 — 대부분의 IdP 가 RS256 이다.

함께 없는 것: `kid`/JWKS 회전, `nbf` 검사, `nonce` 검사, PKCE. Authorization Code 의
`state` 는 서버가 저장하지 않고 브라우저 `sessionStorage` 에서만 대조한다.

- 위치 — `src/api/auth.ts:72-121` · `src/bin/barycenterd.ts:499-511` · `src/api/oidc-code.ts`
- 고치는 법 — `BARY_OIDC_JWKS_URL` 또는 PEM 파일 경로를 받아 `createPublicKey` 로
  `KeyObject` 를 만든다. PKCE(S256)를 붙이고 `nonce` 를 발급·검증한다.

### S-07 · Medium — ID Token 의 `role` 클레임을 네임스페이스 없이 그대로 신뢰

`principalFromIdToken` 은 페이로드의 최상위 `role` 을 읽어 바로 스코프로 바꾼다. IdP 가
사용자 프로필 필드를 클레임으로 흘리거나 셀프서비스 등록을 허용하면 **사용자가 자기 role
을 정한다.** `azp`/`client_id` 검사도 없어서, 같은 issuer 의 다른 클라이언트가 발급한
토큰도 `aud` 만 맞으면 통과한다.

- 위치 — `src/api/auth.ts:118-120`
- 고치는 법 — 클레임 이름을 설정 가능하게 하고(`https://barycenter/role` 같은 네임스페이스),
  기본은 **클레임 → 역할 매핑표**를 요구한다. `azp` 를 `clientId` 와 대조한다.

### S-08 · Medium — admin 평면에 인증이 없고, 백엔드가 그 포트를 겨누는 것을 막지 않는다

`127.0.0.1:19999/membership` 은 인증 없이 밸런서 슬롯을 **덮어쓴다**. `/acme` 는 챌린지
토큰을 심는다. "루프백 전용" 이 유일한 보호인데, `assertAdminPortFree` 는 **리스너 포트만**
검사하고 **백엔드는 안 본다.**

같은 컨테이너 안이므로, 풀 하나가 `127.0.0.1:19999` 를 백엔드로 갖고 그 풀로 가는 라우트가
있으면 **외부 요청이 admin 표면에 그대로 닿는다.** 트래픽을 임의 peer 로 돌리거나 ACME
챌린지를 심을 수 있다.

`/membership/read` 와 `/acme/read` 의 Lua 는 쿼리 파라미터 `epoch` 를 **이스케이프 없이
Lua 패턴에 이어 붙인다** (`k:match("^slot:(.+):" .. epoch .. "$")`).

- 위치 — `src/control/membership.ts:141-247` · `src/control/plane.ts:741-752`
- 고치는 법 — 검증기가 백엔드 `host:port` 가 admin 포트를 겨누는 것을 거부한다. admin
  엔드포인트에 공유 비밀 헤더를 요구한다(세대에 구워 넣으면 된다). epoch 은 `%`
  이스케이프하거나 `[0-9]+` 만 받는다.

### S-09 · Low — 드라이버 무결성 검사 TOCTOU

`loadDriver` 는 `readFileSync` 로 바이트를 읽어 sha512 를 대조한 뒤, **같은 경로를 다시**
`import()` 한다. 그 사이 파일이 바뀌면 검사를 통과한 바이트와 실행되는 바이트가 다르다.
그리고 해싱 대상은 엔트리 파일뿐이라, 드라이버가 `import` 하는 다른 파일은 핀 밖이다 —
"공급망이 설정 파일이 되지 않게" 라는 목적을 절반만 달성한다.

- 위치 — `src/dp/loader.ts:155-165`
- 고치는 법 — 읽은 바이트를 `data:` URL 이나 `vm.SourceTextModule` 로 직접 로드하거나,
  최소한 fd 를 열어 둔 채 `fstat` 로 동일성을 확인한다. 번들된 단일 파일을 요구하고 그
  사실을 계약으로 적는다.

### S-10 · Low — 보안 헤더 0 · 레이트리밋 0 · 컨테이너 root

응답에 `X-Content-Type-Options`·`X-Frame-Options`·CSP 가 하나도 없다. GUI 는 인증 없이
서빙되므로 clickjacking 이 열려 있다. 토큰 인증에 시도 제한이 없어 해시 대조를 무제한
반복할 수 있다(토큰이 충분히 길면 실질 위험은 낮다). `serveGui` 의 이탈 검사는
`relative()` 기반이라 `..` 은 막지만 **루트 안의 심볼릭 링크는 안 본다.** Dockerfile 에
`USER` 가 없어 에이전트가 root 로 돈다 — S-01 의 파급을 키운다.

- 위치 — `src/api/server.ts` · `src/web/serve-gui.ts:17-39` · `deploy/Dockerfile`
- 고치는 법 — 정적/JSON 응답에 `nosniff`·`frame-ancestors 'none'` 을 붙인다.
  `realpathSync` 로 심볼릭 링크까지 확인한다. 에이전트를 전용 uid 로 내리고 필요한
  경로에만 쓰기를 준다.

### S-11 · Low — 사용자 문자열 셋이 검증을 안 거치고 디렉티브로 간다

모듈은 *"어떤 사용자 문자열도 raw nginx 디렉티브로 흘러들지 않는다"* 를 계약으로 적어
뒀지만, 실제로 검증기를 지나지 않는 값이 셋 있다.

1. **`redirect.to`** — `return 301 "<to>"` 로 나간다. nginx 는 **인용된 문자열 안에서도
   변수를 보간한다**. `$http_x` 같은 값을 넣으면 그대로 치환되고, 제어문자를 넣으면
   `lit()` 이 일반 `Error` 를 던져 **422 가 아니라 500** 이 된다. 오픈 리다이렉트 제한도 없다.
2. **`pathPrefix`** — 문법 검사가 전혀 없다. `/` 로 시작하지 않아도 되고 `^~` 같은 값이면
   apply 시점 `nginx -t` 에서 터진다.
3. **`backend.host`** — 인용 덕에 주입은 막히지만 검증이 없어 `nginx -t` 실패가 저장이
   아니라 **게시 시점**에 난다.

이미 만들어 둔 `validateHeaderValue`(변수 화이트리스트까지 구현돼 있다)는 **어디서도
호출되지 않는다.**

- 위치 — `src/conf/render.ts:455` · `src/validate/strings.ts:144-166` (미사용) · `src/model/decode.ts:207-212`
- 고치는 법 — `redirect.to` 에 `validateHeaderValue` 를 붙이거나 URL/경로 문법으로 좁힌다.
  `pathPrefix` 는 `^/[\w\-./~%]*$` 정도로, `backend.host` 는 `normalizeHost` 또는 IP 로 받는다.

## 3. 버그와 오작동

### B-01 · High — HSTS · 암호군 · SNI 불일치 · http2 · 워커 타임아웃이 DB 에 저장되지 않는다

해독기는 `tlsPolicy.hsts`·`cipherPolicy`·`sniHostMismatch`, 리스너 `http2`, 모델
`engine.workerShutdownTimeoutS` 를 **전부 받는다.** 렌더러도 **전부 읽는다.** 그런데 그
사이의 저장소가 없다.

```sql
-- 008_tls.sql
CREATE TABLE tls_policies (
  id, key, name, min_version, max_version, version, …
  -- hsts · cipher_policy · sni_host_mismatch 컬럼이 없다
);
```

`applyOp` 의 `tlsPolicy` 분기는 `min_version`/`max_version` 만 INSERT 하고, `readModel` 은
그 둘만 SELECT 한다. 리스너에는 `http2` 컬럼이 없고, `engine` 은 어떤 테이블에도 없다.
매니페스트 export 도 리소스 종류만 훑으므로 `engine` 을 안 담는다.

**결과** — API 로 HSTS 를 켜면 PATCH 200, plan 초록, commit 성공, 그리고 렌더된 conf 에
`add_header Strict-Transport-Security` 가 **없다.** `http2:false` 로 끄면 무시되고
기본값(켬)이 그대로 간다. `workerShutdownTimeoutS` 가 없으니 세대 GC 의 **시간 보호도
영원히 안 걸린다**(`plane.ts:812` 이 그 값을 읽는데 언제나 `undefined` 다).

- 위치 — `src/store/migrations/008_tls.sql:25-39` · `src/store/config-store.ts:513-527` ·
  `src/store/config-store.ts:258-266` · `src/control/plane.ts:812`
- 고치는 법 — 마이그레이션으로 컬럼을 더하고 `applyOp`/`readModel`/`exportManifest` 를
  맞춘다. 근본 대책은 **왕복 테스트**다: 임의 모델을 commit 하고 `modelAt` 으로 되읽어
  같은지 확인하면 이 부류가 전부 한 번에 잡힌다.

### B-02 · High — 런타임 capability 에 `http2`·`sslConfCommand` 를 안 넘긴다

`writeBootstrap`(:133-143)은 다섯 개를 전부 넘기는데, **정작 서비스가 쓰는
`renderCaps`(:190-200)는 세 개만** 넘긴다.

```ts
// writeBootstrap
{ streamRealip, httpLua, streamLua, http2, sslConfCommand }

// main()  ← ConfigStore · ControlPlane 이 쓰는 것
{ streamRealip, httpLua, streamLua }
```

`caps.http2 === true` 가 절대 참이 아니므로 **HTTP/2 가 영원히 꺼진다** — 엔진이 지원해도.
게다가 검증기는 `http2:true` 를 명시한 리스너를 `option_not_supported` 로 **저장 거부**
하므로, 켜려고 하면 오히려 막힌다. `sslConfCommand` 가 없으니 `ssl_conf_command
Ciphersuites` 도 안 나가고 **TLS 1.3 암호군은 엔진 기본값**으로 남는다 — 암호군 정책의
절반이 무효다.

- 위치 — `src/bin/barycenterd.ts:190-200` vs `:133-143`
- 고치는 법 — capability 매핑을 **함수 하나**로 뽑아 두 자리가 같은 것을 쓰게 한다.
  두 번 적었으니 한 번 갈렸다.

### B-03 · High — `import --mode replace` 와 `POST /restore` 의 삭제 순서가 FK 역순

`importPatch` 는 `have` 맵의 삽입 순서, 즉 `pool → backend → certificate → tlsPolicy →
listener → route …` 순으로 delete 를 만든다. 그런데 DDL 은 반대 방향이다 —
`listeners.default_pool_id → pools ON DELETE RESTRICT`,
`http_routes.listener_id → listeners ON DELETE RESTRICT`.

그래서 **리소스를 지우는 복구는 첫 delete 에서 FK 위반**으로 죽고 `422
reference_violation` 이 된다. 같은 파일의 `rollbackTo` 는 라우트 → 리스너 → 풀 순서로
**정확히 반대로** 지운다 — 코드베이스가 올바른 순서를 알고 있는데 이 경로만 안 맞춘 것이다.

- 위치 — `src/store/manifest.ts:146-154` vs `src/store/config-store.ts:935-941` ·
  `001_init.sql:134-138, 212`
- 고치는 법 — delete 를 `KINDS` 역순으로 낸다. 백업 → 리소스 삭제 → 복구 왕복을 e2e 로
  못 박는다.

### B-04 · High — 드레인은 시작만 되고 해제할 방법이 없다

`backend_drain` 에 행을 넣는 코드는 있는데 **지우는 코드가 없다.** API 에도 CLI 에도
undrain 이 없다. 한번 드레인한 백엔드는 DB 를 손으로 고치기 전까지 영원히 멤버십에서 빠진다.

`deadline_s` 는 API 가 받아서 `deadline_at` 에 저장하지만 **읽는 코드가 없다** — 만료돼도
아무 일이 안 일어난다. 테이블에 백엔드 FK 가 없어서 백엔드를 지웠다 같은 key 로 다시
만들면 **드레인이 조용히 되살아난다.**

- 위치 — `src/control/drain.ts:60-85` · `src/store/migrations/010_drain.sql`
- 고치는 법 — `DELETE /backends/:id/drain` 을 연다. `drainKeys` 가
  `WHERE deadline_at IS NULL OR deadline_at > now()` 로 읽게 한다. `backend_health` 와
  함께 백엔드 삭제 시 정리한다.

### B-05 · Medium — 인증서의 실제 SAN 이 호스트를 덮는지 아무도 안 본다

`certCoversHost` 가 SAN 기준 커버리지를 정확히 구현하고 단위 테스트도 있지만 **프로덕션
호출자가 없다.** 검증기의 `sni_binding_missing` 은 *바인딩 패턴*이 호스트를 덮는지만 본다.

그래서 `a.test` 를 SAN 이 `b.test` 뿐인 인증서에 바인딩해도 검증·plan·commit·apply 가
전부 통과하고, handshake 에서 **커버하지 않는 인증서가 제시된다.** 주석이 "S17 이 겨눈
실패" 라고 적어 둔 바로 그것이다. `SecretStore.facts` 에 SAN 이 이미 저장돼 있어 재료는
다 있다.

- 위치 — `src/dp/certinfo.ts:128-138` (미사용) · `src/validate/model.ts:552-566`
- 고치는 법 — `ValidationCapabilities` 에 `facts(ref)` 를 넘겨, 자료가 있는 인증서에 대해
  바인딩 호스트가 SAN 에 덮이는지 확인한다. 자료가 없으면(ACME 발급 전) 건너뛴다.

### B-06 · Medium — SSE 가 스냅샷 도중 끊기면 구독이 영구 누수된다

`openEventStream` 은 `await snapshot()`(DB 쿼리 두 개) **다음에** `req.on('close')` 를
건다. 그 사이에 클라이언트가 끊으면 `close` 는 이미 발생한 뒤이고, 그러면 **Promise 가
영원히 resolve 되지 않고** `drop()` 도 안 불린다.

죽은 구독이 `EventHub` 에 쌓이고, 이후 모든 `publish` 가 파괴된 응답에 `res.write` 를 한다.
새로고침을 반복하는 GUI 나 재연결하는 스크레이퍼가 이걸 계속 만든다. 백프레셔 처리도
없어서(`res.write` 반환값 무시) 느린 구독자가 메모리를 늘린다.

- 위치 — `src/api/events.ts:75-87`
- 고치는 법 — `req.on('close')` 를 `writeHead` 직후, 스냅샷 *전에* 건다. `res.destroyed` 를
  확인하고 `writeSse` 를 try/catch 로 감싸 실패한 구독자를 해지한다.

### B-07 · Medium — HTTP 헬스 프로브가 상태 코드를 무시한다

`probeHttp` 는 본문이 비어 있지 않으면 **산 것으로 판정한다.** 500·502·503 과 함께 온
에러 페이지는 본문이 있으므로 `healthy` 다. 기본 경로는 `/` 이고 경로·기대본문을 설정할
API 도 없다(`HttpProbeOpts` 는 있지만 `HealthProber` 가 안 넘긴다).

부수적으로 프로브는 모든 백엔드를 `Promise.all` 로 동시에 찌르고 백엔드마다 트랜잭션을
하나씩 **순차로** 연다. 백엔드가 수백 개면 2초 주기를 못 지키고 `#running` 가드가 틱을
통째로 건너뛴다.

- 위치 — `src/control/health.ts:89-113`, `:166-233`
- 고치는 법 — `res.statusCode` 를 판정에 넣고(`2xx` 기본, 허용 범위 설정 가능), 풀에
  `healthCheck { path, expectStatus, expectBody }` 를 모델 필드로 연다. DB 갱신은 한
  트랜잭션에 묶고 프로브 동시성에 상한을 둔다.

### B-08 · Medium — `health_events` 는 쓰기만 하고 읽는 곳이 없다

마이그레이션 주석은 *"이벤트 로그가 단일 정본이다"* 라고 선언하고, 커서를 `FOR UPDATE` 로
잠가 커밋 순서를 보장하는 정교한 장치까지 만들어 뒀다. 그런데 `health_events` 를 `SELECT`
하는 코드가 **`src/` 전체에 한 줄도 없다.** replay 는 실제로 `projectHealth()` 의 상태
재계산으로 대체됐다.

남은 것은 비용뿐이다 — 판정이 바뀔 때마다 단일 행 잠금으로 직렬화되고, 테이블은 **보존
정책 없이 영원히 자란다.** `audit`·`config_revisions`·`plans`·`changesets` 도 마찬가지로
정리 코드가 없다.

- 위치 — `src/control/health.ts:132-145` · `src/store/migrations/006_health.sql`
- 고치는 법 — 감사 목적이면 그렇게 적고 보존 정책(예: 30일)과 정리 잡을 붙인다. 아니면
  커서·잠금과 함께 지운다. 지금은 쓰지 않는 정합성 장치의 비용만 내고 있다.

### B-09 · Medium — 멤버십 갱신마다 DNS 조회, 하나만 실패해도 전부 실패

`resolveSlots` 는 **모든 peer 에 대해 매번** `dns.lookup` 을 부른다. 캐시도 TTL 추적도
없다. 그리고 하나라도 던지면 `Promise.all` 이 거부되어 **그 평면의 멤버십 갱신 전체가
실패한다** — 헬스 프로젝션이든 apply 든.

호스트명 백엔드 하나가 잠깐 안 풀리면 나머지 전부의 헬스 반영이 멈춘다. 해석된 IP 는
다음 갱신까지 고정되므로 DNS 변경 반영도 갱신 시점에만 일어난다.

- 위치 — `src/control/membership.ts:111-128`
- 고치는 법 — `Promise.allSettled` 로 바꾸고 실패한 peer 만 빼면서 로그를 남긴다. TTL
  캐시를 두고, 해석 실패가 계속되면 헬스 `unhealthy` 로 이어지게 한다.

### B-10 · Medium — 지운 백엔드의 헬스 판정이 남아 같은 key 재생성을 즉시 배제한다

`backend_health` 는 `backend_key` 가 PK 이고 FK 가 없다. 백엔드를 지워도 행이 남는다. 같은
key 로 새 백엔드를 만들면 `reduceMembership` 이 남아 있던 `unhealthy` 를 보고 **처음부터
멤버십에서 뺀다** — 프로버가 다음으로 판정을 뒤집을 때까지. `probe_start_seq` 도 이어져서
새 백엔드의 첫 관측이 낡은 것으로 버려질 수 있다.

- 위치 — `src/control/health.ts:268-303` · `006_health.sql`
- 고치는 법 — 백엔드 삭제 시 `backend_health`·`backend_drain` 행을 함께 지운다(또는
  `backends.id` 를 키로 쓴다).

### B-11 · Low — 잘못된 입력이 4xx 가 아니라 500 으로 나가는 자리 셋

1. `decodeURIComponent(hit.m[i+1])` 가 `try` 블록 **밖**에 있다 — `GET /api/v1/plans/%` 는
   `URIError` → 500.
2. `/audit?limit=-5` → `Math.min(-5, 1000)` → PG 가 `LIMIT must not be negative` 로 거부 → 500.
3. `rollbackTo` 의 `BigInt(revision)` 는 숫자가 아닌 입력에 `SyntaxError` 를 던진다.

- 위치 — `src/api/server.ts:776` · `:621` · `src/store/config-store.ts:914`
- 고치는 법 — 파라미터 해독을 `try` 안으로 옮기고, `limit` 에 하한 1 을 건다.
  `to_revision` 은 `/^\d+$/` 로 먼저 본다.

### B-12 · Low — shared dict 크기가 하드코딩이고 `in:` 카운터가 무한 누적된다

`lua_shared_dict bary_http 1m`, `bary_acme 64k` 가 고정값이다. 이 dict 에는 epoch 별 슬롯,
라운드로빈 카운터, 그리고 **peer 별 `in:<host:port>` 카운터**가 함께 산다. peer 카운터는
지우는 코드가 없어 한번 본 peer 는 영원히 남는다.

dict 가 차면 nginx 는 LRU 로 밀어낸다. 밀려난 것이 `slot:` 이면 `balancer_by_lua` 가
`ngx.exit(ngx.ERROR)` 를 타고 **그 풀의 모든 요청이 끊긴다.** ACME 도 같은 이유로 별도
dict 를 쓰고 있지만 64k 라는 값 자체가 조정 불가다.

- 위치 — `src/conf/render.ts:1023-1026, 1115`
- 고치는 법 — `model.engine` 에 dict 크기를 열거나 백엔드 수에 비례해 계산한다. `in:`
  카운터에 `exptime` 을 주거나 멤버십에서 빠진 peer 를 정리한다. dict 사용량을 메트릭으로
  노출한다.

### B-13 · Low — changeset patch 에 누적 상한이 없다

`patchChangeset` 은 `patch = patch || $2::jsonb` 로 무한히 누적한다. 한 요청은 4 MiB 로
제한되지만 **같은 changeset 에 반복 PATCH 하는 총량**에는 상한이 없다. `plan()` 과
`commit()` 이 그 전부를 순차 적용하므로, 누적된 changeset 하나가 커밋 트랜잭션을 오래 잡는다.

- 위치 — `src/store/config-store.ts:682-697`
- 고치는 법 — 누적 op 개수·바이트에 상한을 두고 넘으면 409 로 거절한다.

### B-14 · Low — 죽은 코드와 죽은 import

`poolsReachedBy` 가 `render.ts:27` 과 `validate/model.ts:18` 양쪽에서 import 되지만
**둘 다 안 쓴다.** `validateHeaderValue`(S-11), `certCoversHost`(B-05),
`checkEngineConstraints`(S-04) 도 호출자가 없다. `EngineCapabilities.supports.sniPassthrough`
와 `stream` 은 조회는 하지만 아무 판정에도 안 쓰여, `ssl_preread` 없는 엔진에서
tls_passthrough 리스너가 **저장·plan 을 통과하고 apply 에서 터진다.**

- 위치 — `src/conf/render.ts:27` · `src/validate/model.ts:18` · `src/engine/capabilities.ts:94-97`
- 고치는 법 — 배선하거나 지운다. `noUnusedLocals` 는 import 를 안 잡으므로 린트 규칙을 추가한다.

### B-15 · Low — DP Agent 의 `terminal` 원장은 설계상 절대 안 잘린다

`completed` 와 `activationEvidence` 는 각각 64 개로 가지치기되지만 `terminal` 은
**의도적으로 안 자른다** — 지연 RPC 부활 방지 장치이기 때문이다. 코드 주석이 이 부채를
정확히 인정하고 자를 규칙의 스케치까지 적어 뒀지만 아직 미구현이다. 전환 × 평면마다 한
항목씩 `agent.json` 에 영구히 쌓이고, 그 파일은 **매 저장마다 통째로 직렬화**된다.

`legacyTerminalKey` 폴백은 44차 이전 포맷 키를 영원히 조회하므로 그 범위에서는 옛
`aborted` 가 **어떤 새 토큰도 영구히 막는다.**

- 위치 — `src/dp/agent.ts:2152-2205, 2243-2264`
- 고치는 법 — 주석의 스케치대로 `terminal` 값에 epoch 을 담고, 좌표에 추월된 항목을
  자른다. `bary_agent_state_bytes` 에 알람을 건다(메트릭은 이미 있다).

### B-16 · Low — 리더 재획득이 옛 PG 커넥션을 정리하지 않는다

`tryAcquire` 는 `#lost` 가 참이면 새 `pg.Client` 를 만들고 `this.#client` 를 덮어쓴다.
**옛 클라이언트를 `end()` 하지 않는다.** 세션이 흔들릴 때마다 커넥션이 하나씩 샌다. 종료
경로에서 `FileStore.release()` 도 안 불려서(SIGTERM 핸들러가 안 부른다) 락 파일이 남는다 —
Linux 에서는 `/proc` 시작 시각으로 회수되지만 그 폴백에 기대는 셈이다.

- 위치 — `src/control/leader.ts:71-117` · `src/bin/barycenterd.ts:545-563`
- 고치는 법 — 새로 잡기 전에 옛 클라이언트를 `end()` 한다. `stop()` 에서 store 를
  `release()` 한다.

## 4. 신규로 넣으면 좋을 것

운영에 실제로 걸리는 순서로 적었다. 1–4 는 위 결함들이 다시 안 생기게 하는 장치이고,
5부터는 이 제품이 현장에서 요구받을 기능이다.

1. **모델 왕복 속성 테스트** — 임의 모델 → commit → `modelAt` → 같은 모델. B-01 부류(필드는
   있는데 저장 안 됨)를 한 번에 전부 잡는다. 이 저장소가 반복해서 밟는 함정이라 우선순위가
   가장 높다.
2. **"호출자 없는 export" 게이트** — S-04·B-05·B-14 는 전부 *테스트는 초록인데 배선이 없다*
   였다. 공개 표면 동결 테스트가 이미 있으니, 같은 자리에 도달성 검사를 붙인다.
3. **리소스 `key` 문법 계약** — 해독기 + DB CHECK + SecretStore 이름 규칙을 하나로 통일한다.
   S-01 을 닫고, ACME 가 `acme-<key>` 를 SecretStore 에 넣다 실패하는 불일치도 없앤다.
4. **제어 API TLS 와 mTLS** — 개인키와 Bearer 토큰이 지나는 채널이다. 서버 TLS 를 먼저,
   그다음 클라이언트 인증서로 CLI·스크레이퍼 인증을 열면 토큰 유출 표면이 줄어든다.
5. **백엔드별 헬스체크 정의** — 경로·기대 상태·기대 본문·간격·임계값을 풀 모델에 연다.
   지금은 `GET /` 에 본문 비어 있지 않으면 healthy 라는 고정 정책뿐이다(B-07).
6. **레이트리밋과 커넥션 제한** — `limit_req`·`limit_conn` 은 리버스 프록시에 사실상
   필수인데 모델에 없다. AST 와 렌더러 구조상 추가 비용이 낮다.
7. **요청·응답 헤더 조작** — `validateHeaderName`/`validateHeaderValue` 가 변수 화이트리스트
   까지 이미 구현돼 있다. 렌더러의 `add_header` 상속 함정(주석에 실측이 적혀 있다)만
   지키면 바로 열 수 있다.
8. **타임아웃·버퍼·본문 크기 프로필** — `proxy_connect_timeout`·`proxy_read_timeout`·
   `client_max_body_size` 가 전부 nginx 기본값 고정이다. 실서비스 전환 시 가장 먼저 요구받는다.
9. **운영 상태 조회 API** — 지금 드레인·헬스는 부분적으로만 보인다. 백엔드별
   `{admin_state, health, drain, 현재 슬롯 소속}` 을 한 번에 주는 엔드포인트가 있으면
   "왜 이 백엔드가 트래픽을 안 받나" 에 한 번에 답한다.
10. **보존 정책과 정리 잡** — `audit`·`health_events`·`config_revisions`·`plans`·
    `changesets`·`terminal` 원장 모두 상한이 없다. 세대·시크릿에는 이미 상한이 있으니 같은
    모양을 DB 쪽에도 만든다.

## 5. 어떻게 확인했나 · 한계

문서·주석의 주장은 근거로 쓰지 않았다. 주석이 "막았다" 고 적은 것이 실제로 막혀 있는지는
호출 그래프로 확인했고, 판정이 갈리는 네 건은 코드를 **실행해서** 확인했다.

- **S-01** — `materializeGeneration` 에 `key='../../../../pwned'` 를 넣어 prefix 밖 파일
  생성과 `verifyGeneration` 통과를 재현했다.
- **S-02** — https + `acceptProxyProtocol` 모델을 렌더해 `real_ip_header` 부재를 확인했다.
  `streamRealip:false` 로는 검증기가 거부하는 것도 확인했다.
- **B-01 · B-02** — DDL 컬럼 목록과 `applyOp`/`readModel`/`renderCaps` 를 직접 대조했다.
- **기준선** — `tsc --noEmit` 통과, `vitest run tests/unit` 50파일 520테스트 전부 통과.

**못 본 것** — PostgreSQL 이 필요한 `tests/store`·`tests/e2e`, 실제 엔진이 필요한
`tests/engine`, 그리고 `src/dp/apply.ts`·`src/dp/agent.ts` 의 전환 상태기계는 구조와 성장
특성만 봤고 모든 분기를 검증하지 않았다. B-03 은 DDL 과 코드 순서를 대조해 확정했지만
실제 PG 에서 재현하지는 않았다.
