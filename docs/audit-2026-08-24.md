## 2. 결함

### D1 — `expandVersionRoots` 가 자기 인자를 못 받아 세대 root 가 무효다 · **High**

`collectSecretRoots` 는 GC root 를 넷 모은다. ② 는 *디스크에 남아 있는 세대가 참조하는
인증서 버전*이고, 세대 디렉토리는 시크릿 이름을 모르므로 `@<version>` 자리표만 넣는다.
그 자리표를 실제 참조로 넓히는 것이 `expandVersionRoots(roots, allRefs)` 이고,
`allRefs` 는 **저장소에 실재하는 참조 전부**여야 한다.

데몬은 이렇게 부른다.

```js
const raw   = await collectSecretRoots({ db, prefix });
const all   = [...raw].filter((r) => !r.startsWith('@'));  // ← 이미 root 인 것들
const roots = expandVersionRoots(raw, all);
```

`all` 이 *이미 root 인 참조*라서 넓히기가 더할 수 있는 것이 하나도 없다. 그리고 함수는
`@` 자리표를 결과에서 빼므로 **root 부류 ② 가 통째로 사라진다.** 남는 보호는
①(최근 20 리비전) · ③ · ④ 와 `keepPerName=2` · `minAgeMs=1h` 뿐이다.

도달 경로: 세대 하나가 아직 디스크에 있는데(`keep=10` 안) 그 세대가 쓰는 인증서 버전이
최근 20 리비전 밖으로 밀리고, 같은 이름의 새 버전이 둘 이상 쌓이면 GC 가 **살아 있는
개인키를 지운다.** 증상은 `secret-gc.ts` 머리말이 적어 둔 그대로다 — 열린 fd 로 트래픽은
계속 흐르고 **다음 reload 만 깨진다.**

- `src/bin/barycenterd.ts:504–506` — 호출부
- `src/control/secret-roots.ts:95` — `expandVersionRoots`
- `tests/unit/secret-gc.test.ts:154` — 함수는 **올바른** 인자로 단위 테스트된다. 그래서 못 잡는다

**처방.** `allRefs` 에 저장소의 실제 참조 목록을 넣는다. `FsSecretStore.versions(name)` 이
그 재료인데 **호출자가 0 개다** — 도달성 게이트가 클래스 *메서드*는 안 세기 때문에 안
걸렸다(→ G6). `listRefs()` 를 하나 내고 데몬이 그것을 넘긴다. 그리고 이 **배선**을
겨누는 계약 테스트가 필요하다: 세대에만 있는 버전을 만들어 놓고 sweep 이 그것을 남기는지 본다.

### D2 — 멤버십 평면에서 `Backend.weight` 를 아무도 안 읽는다 · **High**

정적 `server` 줄 경로는 가중치를 낸다 —
`if (b.weight !== 1) args.push(lit(\`weight=${b.weight}\`))` (`render.ts:305`).
그런데 Lua 가 있는 엔진(= 이 제품의 기본 배포)에서는 upstream 이
`balancer_by_lua_block` 이 되고, 슬롯은 `slotsOf` 가 만든 `host:port` 문자열 목록이다.
`src/control/membership.ts` 에는 `weight` 라는 낱말이 **한 번도 안 나온다.**
`pickExpression` 의 round_robin · hash · least_conn 셋 다 균등하게 고른다.

즉 **같은 모델이 엔진에 따라 다르게 밸런싱된다.** 사용자는 저장에 성공하고, GUI 와 CLI 는
값을 되돌려 주고, plan 도 아무 말을 안 한다.

`render.ts` 가 `source_ip_hash` 에 대해 정확히 같은 함정을 이미 한 번 잡았다 —
*"필드는 있는데 아무도 안 지키는 상태였다. 이 저장소가 반복해서 잡아 온 바로 그 부류다."*
가중치는 그때 같이 안 봤다.

- `src/control/membership.ts:45–70` — `slotsOf` 가 weight 를 안 싣는다
- `src/conf/render.ts:388–430` — `pickExpression` 이 균등 선택

**처방.** 셋 중 하나. 무엇을 고르든 **지금처럼 조용한 것**보다 낫다.

1. 슬롯 문자열에 가중치를 실어(`host:port|w`) Lua 가 가중 선택을 한다 — 계약이 넓어진다
2. 가중치를 *슬롯 목록의 반복*으로 편다 — 가장 싸고, dict 크기를 먹는다
3. `weight !== 1` 인데 멤버십 평면이면 `capabilityWarnings` 에 실어 plan 이 말한다 —
   최소한 거짓말은 아니게 된다

### D3 — 업스트림 재시도마다 `in:` 카운터가 영구히 샌다 · **Medium**

`balancer_by_lua_block` 은 peer 를 고를 때마다 `d:incr("in:" .. peer, 1, 0)` 하고
`ngx.ctx.bary_peer = peer` 로 **덮어쓴다.** `log_by_lua_block` 은 그 *마지막* peer 하나만
내린다.

nginx 는 `proxy_next_upstream error timeout` 이 기본으로 켜져 있고 렌더러는 그것을 끄지
않는다(`grep -rn next_upstream src/` → 0 건). 그래서 연결 실패로 한 번이라도 재시도가
나면 첫 peer 의 카운터가 **+1 인 채로 영원히 남는다.** 0 이 될 때만 TTL 이 걸리므로
(`INFLIGHT_IDLE_TTL`) 만료로도 안 사라진다.

결과는 둘이다.

- `least_conn` 이 그 peer 를 영구히 「바쁜 것」으로 본다
- 드레인이 `quiesced` 를 **영영 못 받는다** — `/membership/inflight` 가 0 을 안 답한다.
  S2 가 두 평면에 창구를 낸 것이 이 판정을 위해서였는데, 판정 자체가 안 선다

- `src/conf/render.ts:350–351` — 올리는 자리
- `src/conf/render.ts:1403–1409` · `1513–1518` — 내리는 자리(양 평면)

**처방.** `ngx.ctx` 에 *고른 peer 하나*가 아니라 **고른 것 전부**를 쌓고, log 단계에서 그
목록을 전부 내린다. 다섯 줄이다. 골든이 필요하다 — 첫 백엔드를 죽여 두고 요청 하나를
보낸 뒤 `/membership/inflight` 가 둘 다 0 을 답하는지 본다.

### D4 — 퇴역한 epoch 의 `slot:` 키를 아무도 안 지운다 · **Medium**

`/membership` 은 `d:set("slot:" .. name .. ":" .. epoch, peers)` 를 **만료 없이** 쓴다.
ACME 토큰에는 `remove` 동사와 TTL 이 둘 다 있는데 슬롯에는 둘 다 없고, 지우는 코드도
어디에도 없다(`membership.ts` 의 `d:delete` 는 ACME 토큰용 한 줄뿐이다).

dict 는 프로세스 수명이므로 nginx 재시작 전까지 **세대 전환마다 풀 수만큼 키가 쌓인다.**
그 끝은 이 저장소가 이미 두 곳에 적어 뒀다 — 차면 LRU 가 밀어내고, 밀려난 것이 `slot:`
이면 `balancer_by_lua` 가 `ngx.exit(ngx.ERROR)` 를 타 **그 풀의 모든 요청이 끊긴다.**

`membershipDictKb` 를 연 것(B-12)이 그 절벽을 뒤로 미는 손잡이인데, **미는 것과 안
자라게 하는 것은 다르다.**

- `src/control/membership.ts:222–240` — `/membership` 쓰기
- `src/conf/render.ts:139–144` · `src/model/provisional.ts:636–650` — 절벽을 적어 둔 자리

**처방.** 세대 GC 가 이미 「이 세대는 아무도 안 든다」를 판정한다(`retention.ts` 의
`workerLingerMs`). 같은 판정으로 `DELETE /membership?epoch=<퇴역 epoch>` 를 함께 보내면
된다 — ACME 의 `remove` 와 같은 모양이라 새 계약이 아니다. 그때까지는
`bary_membership_slot_keys` 게이지를 하나 내 **자라는 것이 보이게**라도 해 둔다.

### D5 — 무관한 error log 한 줄이 apply 를 통째로 실패시킨다 · **Medium**

`provesActivation` 은 `errorLogGrowth > 0` 이면 활성화가 아니라고 판정한다
(`operation.ts:119`). 워터마크는 HUP 직전에 찍고, 증가분은 `error.log` 의 **줄 수 차이**다
— 어떤 줄인지는 안 본다.

그런데 nginx 는 `upstream timed out` · `no live upstreams` ·
`SSL_do_handshake() failed` 를 전부 `[error]` 로 적는다. 즉 **트래픽이 있는 프록시에서
클라이언트가 만든 오류 한 줄**이 그 창에 들어오면 멀쩡한 reload 가 「관측되지 않음」이
되고, `RELOAD_ATTEMPT_LIMIT` 를 소진해 apply 가 실패한다. 바쁜 배포일수록 자주 걸린다.

S7 이 이 신호를 넣은 이유(포트 점유를 4027ms → 71ms 로 당겼다)는 옳다. 문제는 **신호의
범위**다 — 겨눈 것은 설정이 만든 실패이지 트래픽이 만든 오류가 아니다.

- `src/dp/operation.ts:119` — 판정
- `src/dp/effects-fs.ts:257–267` — 줄 수만 센다

**처방.** 줄 수 대신 **수준으로 좁힌다.** 설정·기동 실패는 언제나 `[emerg]` · `[alert]` ·
`[crit]` 이고, S7 이 잡은 포트 점유도 `[emerg]` 다. 워터마크 이후 늘어난 줄 중 그 셋만
세면 검출력은 그대로이고 오탐이 사라진다.

### D6 — `weight: 0` 이 저장되고 apply 에서 죽는다 · **Medium** (실물 확인)

해독기는 `int(…, 0, 1_000_000)` 이라 **0 을 받는다**(`decode.ts:649`). `validateModel` 은
weight 를 안 본다. 저작 표면은 반대다 — `putBackendPatch` 가 *"가중치가 1 이상 정수가
아니다"* 로 막는다(`web/edit.ts:38`). 즉 GUI · CLI 로는 못 넣고 API · import 로는 들어간다.

그리고 nginx 는 그것을 안 받는다. 실제 엔진 이미지로 재 봤다.

```
upstream p { server 127.0.0.1:9001 weight=0; }

[emerg] 1#1: invalid parameter "weight=0" in /tmp/nginx.conf:3
nginx: configuration file /tmp/nginx.conf test failed
```

Lua 가 없는 엔진에서 이 값은 **게시 전 `nginx -t` 에서 터진다.** 그때 운영자가 보는 것은
「설정이 이상하다」이지 「가중치 0 은 없다」가 아니다 — `validateBackendHost` ·
`validatePathPrefix` 를 만든 이유(S-11)와 정확히 같은 자리다. Lua 가 있는 엔진에서는
D2 때문에 아무 일도 안 일어난다.

**처방.** 해독기 하한을 `1` 로 올린다. 한 글자다.

### D7 — `rollbackTo` 만 스냅샷을 캐스팅한다 · **Medium**

`modelAt` 의 주석이 이 병을 이름 붙여 놓았다.

> v0.6 이 컬렉션 셋을 더하자 v0.6 이전 리비전으로 롤백하면 `undefined.map` 으로 500 이
> 났다. 캐스팅은 그 순간까지 아무 말도 안 한다.

그래서 `modelAt` 은 캐스팅을 버리고 `decodeModel` 을 지난다. **`rollbackTo` 는 안 지난다.**
같은 컬럼을 직접 읽어 `src['model'] as Model` 로 캐스팅하고(`config-store.ts:1303`) 곧바로
`opsOf(model)` 에 넣는데, `opsOf` 는 여덟 컬렉션에 `.map` 을 건다. 고친 것과 **정확히 같은
병이 옆자리에 남아 있다.**

지금 코드가 만드는 스냅샷은 언제나 여덟 컬렉션이 다 있으므로 **업그레이드를 건넌
데이터에서만** 드러난다 — 그게 이 부류가 매번 늦게 발견되는 이유다.

**처방.** 트랜잭션 안에서 `decodeModel` 을 지나게 한다. `getPlan` 의 `r['model'] as Model`
(`:1376`)도 같은 자리다.

### D8 — `FsSecretStore.put` 이 반쪽으로 죽으면 다시 올려도 안 고쳐진다 · **Medium**

`put` 은 `mkdirSync` 뒤에 파일 셋을 쓰고 `chmodSync(dir, 0o500)` 으로 잠근다. 멱등 판정은
`if (!existsSync(dir))` 하나다.

mkdir 과 첫 write 사이에서 죽으면 **빈 디렉토리가 남고, 같은 바이트를 다시 올려도 그
분기가 건너뛴다.** 참조는 성공으로 돌아가고 자료는 없다 — 그리고 디렉토리가 0500 이라
손으로 고치기도 막힌다.

저장소의 나머지(`materialize.ts`, `store-fs.ts`)는 전부 *임시 → fsync → rename* 을
지키는데 **개인키를 다루는 이 자리만** 안 지킨다. fsync 도 없다.

- `src/dp/secrets.ts:128–140`

**처방.** `materializeGeneration` 과 같은 모양으로 만든다 — `.tmp-<nonce>/` 에 셋을 쓰고
fsync 한 뒤 통째로 rename. 버전이 내용 주소라 이름 충돌이 없으므로 그대로 옮겨 쓸 수 있다.

### D9 — 화면이 하나라도 붙어 있으면 SIGTERM 이 안 끝난다 · **Medium**

종료 경로는 `server.close(cb)` 안에서 락 반납과 리더 사퇴를 한다. 그런데 Node 의 `close`
는 **열린 연결이 전부 끝나야** 콜백을 부르고, `/api/v1/events` 는 설계상 끝나지 않는다 —
화면이 폴링을 안 하는 이유가 그것이다. `closeAllConnections()` 도, 강제 종료 타이머도 없다.

그래서 GUI 를 열어 둔 채 컨테이너를 내리면 이렇게 된다.

- `agentStore.release()` 가 안 돈다 → `agent.json.lock` 이 남는다
- `election.release()` 가 안 돈다 → `released_at` 이 안 적힌다. 「깨끗이 물러난 것」과
  「죽은 것」이 안 갈린다
- 오케스트레이터의 유예 뒤 SIGKILL 로 끝난다

검수 B-16 이 락 반납을 넣은 이유가 *"다음 기동이 `/proc` 폴백에 기대지 않게"* 였는데, 그
반납이 실제로는 대개 안 돈다.

- `src/bin/barycenterd.ts:676` — `server.close()`
- `src/api/events.ts:61–131` — 스트림이 끊길 때까지 await 한다

**참고.** `bary-dp-agent.ts:84–88` 은 같은 함정을 **알고 닫아 뒀다** — `server.close()` 옆에
5 초 상한을 건다. 두 진입점이 갈려 있다.

**처방.** `server.close()` 뒤에 `server.closeAllConnections()` 를 부르고(Node 18.2+),
정리에 유한한 마감을 씌운 뒤 `process.exit` 한다. 열린 SSE 를 먼저 `res.end()` 로 닫아
주면 화면도 「끊겼다」를 안다.

`id` 를 붙이고 있으므로 서버 쪽 절반은 있다.

### G2 — CSP 에 `script-src` 가 없다

`headers.ts` 가 `frame-ancestors 'none'` 만 걸어 두고 *"전체 CSP 는 GUI 빌드가 무엇을
내는지에 달려 있어 함께 정해야 한다"* 고 적었다. 지금 그 빌드는 정적 SvelteKit 산출물이라
**정할 수 있다.** 문서는 인증 없이 나가고 admin 토큰은 `sessionStorage['bary.token']` 에
있으므로, `script-src 'self'` 와 `connect-src 'self'` 는 지금 얻을 수 있는 가장 싼 방어다.

### G3 — 환경변수에 해독기가 없다

모델 경계는 *강제 변환하지 않는다*가 계약인데, 데몬은
`Number(env('BARY_PROBE_INTERVAL_MS', '2000'))` 처럼 **캐스팅**한다. 오타 하나면 `NaN` 이
되고 `setInterval(NaN)` 은 1ms 마다 돈다 — 프로버가 백엔드를 초당 천 번 찌른다.
`parseTokenSpecs` 가 토큰에 대해 세운 규칙을 숫자 환경변수에도 적용하는 헬퍼 하나면 된다.

### G4 — SSE 구독자 상한과 backpressure

`read` 스코프면 `/api/v1/events` 를 몇 개든 열 수 있고, `writable()` 은 `destroyed` 만
보지 `writableLength` 는 안 본다. 안 읽는 소비자 하나가 서버 버퍼를 무한히 키운다.
연결 수 상한과 「버퍼가 임계를 넘으면 끊는다」 한 줄이면 닫힌다.
`remote.ts` 의 응답 수집(`text += c`)도 상한이 없다 — 에이전트 쪽 `readJson` 은 4MiB 를
거는데 CP 쪽만 안 건다.

### G5 — 테스트용 가짜가 `dist` 로 나간다

`FakeEffects` · `FaultStore` · `CrashClock` · `MemoryStore` 가 프로덕션 소스에 살아 배포
산출물에 실린다. 도달성 게이트가 *"의도된 테스트 이음새"* 로 예외 처리해 둔 것들인데,
예외의 이유(주입 계약의 참조 구현)와 **배포에 실리는 것**은 다른 물음이다.
`src/testing/` 로 옮기고 `tsconfig.build.json` 에서 빼면 계약은 그대로 두고 표면만 줄어든다.

### G6 — 도달성 게이트가 클래스 메서드를 안 센다

`reachable.mjs` 는 **export 된 이름**만 본다. 그래서 `FsSecretStore.versions()` 처럼
*호출자 0 개인 public 메서드*는 안 걸리고, 그 메서드가 D1 이 필요로 하던 재료였다.
게이트를 메서드까지 넓히면 같은 부류를 한 번 더 훑을 수 있다.

### G7 — 작은 것 넷

- `readManifest` 가 `JSON.parse` 를 감싸지 않고 `parsed.files` 를 검증하지 않는다 — 깨진
  manifest 가 `GenerationError` 가 아니라 `SyntaxError` · `TypeError` 로 올라온다
- `BARY_LISTEN` 을 `split(':')` 로 가르므로 IPv6 주소를 표현할 수 없다
- `build.sh` 가 `gui/node_modules` 존재만 보고 넘어간다 — `gui/package-lock.json` 이 바뀌어도
  낡은 의존성으로 빌드한다
- `bary-dp-agent` 가 `deploy/` 에 없다. 원격 모드를 냈는데 그 배포 조리법이 없다

## 6. 게이트가 추가로 찾은 것 (수정 중에 나왔다)

G6(도달성 게이트를 클래스 메서드까지)을 넣자 **켜는 순간 여섯이 나왔다.** 넷은 관측
창구라 근거와 함께 예외로 적었고(`scripts/reachable.mjs` 의 `ALLOW`), **둘은 실물이었다.**
손으로 훑은 이 검수가 못 본 것을 기계가 바로 짚었다는 사실 자체가 그 항목의 값이다.

`AcmeStore.upsertAccount` 는 `acme_accounts` 에 넣는 유일한 코드인데 **호출자가

인증서에 `acme` 의도를 적어도 주문이 영영 안 열리고, 로그의 경고 한 줄 말고는 아무
신호가 없다. **ACME 기능 전체가 제품 표면에서 도달 불가다.**

- `src/control/acme-store.ts:81` — `upsertAccount`
- `src/control/acme-runner.ts:109–113` — 없으면 경고하고 건너뛴다

**왜 이 회차에 안 고쳤나.** 배선하려면 표면을 정해야 한다 — REST 라우트인가(B 동결

투두 W4 로 올렸다. 그때까지 `ALLOW` 에 **「부채」라고 이름 붙여** 둔다 — 예외로 적어

### D22 — §8.2 의 주기적 고아 스캔이 배선돼 있지 않았다 · Medium — **닫혔다**

`AcmeRunner.cleanup(olderThanSeconds)` 은 §8.2 가 요구한 *"주기적 고아 스캔"* 이고

S18 이 실측한 그대로 **버려진 주문을 CA 는 안 치운다.** dict 쪽은 `ACME_TTL_SECONDS`
(30 분)가 덮지만 **원장은 안 덮는다** — `cleaned_at` 이 안 적히면 `orphans` 가 영원히
자라고, §8.2 가 그 스캔을 요구한 이유가 사라진다.

## 7. W0 마무리가 찾은 것 — 게이트 자신의 결함

W0 을 닫으려고 **전체** `verify.sh` (도커 스위트 포함)를 처음 끝까지 돌렸다. 그때까지
회차마다 돌린 것은 `--quick` 이었다. 전체를 돌리자 e2e 가 빨갰다.

### N4 — 워크트리에서는 e2e 가 **항상** 빨갛다 · High — **닫혔다**

```
FAIL  e2e (실제 nginx)  —  완료  (676초)
Error: 데몬이 안 떴다:
(컨테이너 로그는 비어 있다)
```

여섯 스위트 중 다섯이 죽었다. 살아남은 하나(`apply-nginx`)는 `barycenterd` 를 컨테이너
안에서 안 돌리는 유일한 스위트다.

**원인은 컨트롤 플레인이 아니라 마운트였다.** e2e 는 저장소를 `-v $(pwd):/app:ro` 로
올리고 컨테이너 안에서 `node /app/dist/bin/barycenterd.js` 를 돌린다. 그 산출물은 `pg`
를 import 한다. 그런데 **git worktree 의 `node_modules` 는 메인 체크아웃을 가리키는
심볼릭 링크**이고, 그 대상 절대경로는 컨테이너 안에 없다:

```
Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'pg'
  imported from /app/dist/control/leader.js
```

**그리고 그 사실이 어디에도 안 드러난다.** 기동 스크립트가 `apk add` 를
`>/dev/null 2>&1` 로 지우고 나머지는 성공 시 조용해서, 실패 메시지에 붙는
`docker logs --tail 40` 이 **빈 문자열**이다. 진단은 컨테이너를 손으로 다시 띄워
`set -x` 를 걸고서야 나왔다.

**⚠️ 몰랐던 게 아니라 산문으로 적어 뒀었다.** 투두의 「착수 전」에 이 줄이 있었다:

> 워크트리에서 e2e 를 돌릴 거면 `rm -f node_modules && npm ci` 를 **먼저** 한다
> (심링크는 컨테이너 안에서 끊긴다)

**그리고 아무도 안 했다** — 이 투두를 쓴 사람이 그대로 안 했다. 이 저장소가
`pinned.mjs` 를 만들며 배운 것과 같다: *"규칙이 산문이라 안 지켜졌으므로 게이트로
옮겼다."* 손으로 할 일을 적는 것은 방어가 아니고, 답은 **그 일이 필요 없게 만드는
것**이었다.

**왜 High 인가.** `CLAUDE.md` 의 규칙이 *"에이전트는 워크트리, 사람은 메인에서 작업"*
이다. 그래서 **에이전트가 돌리는 게이트는 항상 워크트리에서 돈다** — 즉 이 저장소에서
에이전트가 e2e 를 초록으로 볼 수 있는 경로가 없었다. 「거짓 초록」의 반대편인
**「거짓 빨강」**이고, 대가는 다르지만 끝은 같다: 게이트가 말하는 것을 사람이 안 믿게
된다. 이 회차에 실제로 그랬다 — 검수자가 자기 W0 수정이 e2e 를 깼는지 확인하는 데
시간을 썼고, 그동안 e2e 는 **아무 회차의 코드도 안 재고 있었다.**

**왜 워크트리 쪽을 안 고쳤나.** `scripts/pinned.mjs` 도 같은 짓을 한다 —
`symlinkSync(join(process.cwd(), 'node_modules'), join(tree, 'node_modules'), 'dir')`.
워크트리를 만드는 자리는 앞으로도 늘고 전부 같은 이유로 링크를 건다(설치는 분 단위다).
심볼릭 링크가 바인드 마운트를 못 건너는 것은 **도커의 성질이지 누구의 실수가 아니므로**,
고칠 자리는 링크가 아니라 마운트다.

`tests/e2e/mounts.ts` 에 `appMount()` 한 벌을 두고 여섯 자리를 그것으로 바꿨다.
`node_modules` 의 실체 경로를 두 번째 `-v` 로 따로 싣는다. 링크가 아니면 두 번째
마운트가 첫 번째 안의 같은 자리를 덮으므로 **메인 체크아웃에서는 아무것도 안 바뀐다** —
「워크트리일 때만」 이라는 분기를 안 둔 이유가 그것이다. 그런 분기는 워크트리에서
아무도 e2e 를 안 돌리는 동안 조용히 썩는다.

- `tests/e2e/audit-worktree-mounts.test.ts` — 메커니즘을 실물 도커로 못 박는다.
  트리만 올리면 링크가 안 열리고, `appMount()` 로는 열리고, 링크가 아니어도 결과가
  같고, **지금 이 체크아웃의 `pg` 가 컨테이너 안에서 열린다.**

### N4-b — 같은 수정이 `scripts/soak.mjs` 를 빠뜨렸다 · **닫혔다**

N4 를 고친 커밋은 `tests/e2e/` 의 여섯 자리를 바꿨다. **`scripts/soak.mjs` 에도 같은
줄이 있었고, 안 바꿨다.**

```
-v ${process.cwd()}:/app:ro
```

그 커밋의 메시지가 *"목록으로 관리하다 물린 자리가 이미 여럿이다"* 라고 적어 놓고
**같은 회차에 같은 실수를 했다.** 목록이 `grep` 한 번으로 나오는 것이라도, 그 `grep`
을 돌린 범위가 `tests/` 였다는 것이 전부다.

**그리고 이건 게이트가 안 잡는다.** `verify.sh` 에 소크가 없다 — 여기가 깨지면 사람이
손으로 돌릴 때까지 아무도 모른다. 그래서 N4 를 고친 회차에 e2e 는 초록이 됐는데
여기는 그대로였고, W2 마무리에서 소크를 돌리려다 발견했다.

`appMount()` 를 그대로 옮겨 붙였다. **사본이 둘인 것을 안다** — 저쪽은 `.ts` 이고
이쪽은 `.mjs` 라 한 벌로 두려면 빌드 설정을 건드려야 하고, 그 값이 두 줄짜리 인자
배열보다 크지 않다고 판단했다. 대신 사본이 있다는 사실과 **게이트가 안 잡는다는
사실**을 그 자리에 적었다.

**남은 것 하나.** 기동 스크립트가 `apk add` 출력을 지우는 것은 그대로 뒀다. 그 자체는
소음 감축이라 합당하고, 이번에 진단을 막은 것은 **실패 경로에 아무 출력이 없는 것**
이지 `apk` 가 아니다. 다만 `데몬이 안 떴다` 에 붙는 진단이 빈 문자열일 수 있다는 것은
여전히 사실이다 — 컨테이너 상태(`docker inspect`)와 종료 코드를 함께 싣는 것이
다음 값이다. 투두 W3 에 올렸다.
