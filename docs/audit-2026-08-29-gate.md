## 먼저 — 내가 틀렸던 것

읽는 중에 *"CI 의 재현물 핀 검사가 한 커밋만 본다"* 고 판단했다. **틀렸다.**

`verify.sh:243` 이 `pinned.mjs HEAD~1` 을 하드코딩하는 것은 맞다. 그래서 거기서 멈추면
그 결론이 나온다. 그런데 `.github/workflows/verify.yml` 의 `quick` 잡은 **자기 단계를
따로 들고 있고**, 거기서 PR 이면 병합 기준점을, 푸시면 `github.event.before` 를 계산해
`pinned.mjs` 에 넘긴다 — 새 브랜치의 첫 푸시(`before` 가 0)까지 폴백이 있다.

**호출부를 하나만 보고 결론을 냈다.** 이 저장소가 반복해서 적어 둔 *"자리가 둘이면
언젠가 갈린다"* 를 거꾸로 물린 셈이다 — 자리가 둘인 것을 보고 한쪽만 읽었다.

기록에 남기는 이유는 이 회차의 값이 발견 목록에만 있지 않기 때문이다. 게이트를 읽는
사람은 **`verify.sh` 와 워크플로를 함께** 읽어야 한다.

## A. [Medium] 취소가 범위 기반 단계의 커버리지를 끊었다

`verify.yml` 이 같은 ref 의 앞선 run 을 취소했다(`cancel-in-progress: true`, main 포함).
주석은 그 대가를 이렇게 적었다:

> 대가는 명확하다 — **중간 커밋은 자기 run 이 끝까지 안 갈 수 있다.** 검증을 건너뛰는
> 것은 아니다: 그 커밋을 포함한 최신 run 이 곧 판정한다.

**범위를 재는 단계에는 성립하지 않는다.** 다른 단계는 *트리*를 재므로 최신 run 이 곧
판정한다는 말이 참이다. 재현물 핀 검사는 `before..head` 라는 **범위**를 본다:

```
push ①  main A → B    run1 시작 (before=A)
push ②  main B → C    run1 취소, run2 시작 (before=B)   ← A..B 는 어느 범위에도 없다
```

`before` 는 그 push 직전의 위치이므로 다음 run 의 범위는 취소된 run 이 보던 자리를
**지나간 곳에서 시작한다.** 두 push 가 run 하나의 시간 안에 오면 앞 커밋들의 핀 검사는
완료되지 않고, 그 사실은 어디에도 안 남는다.

**제거했다.** 조건부로 만드는 길도 있었지만, 취소가 서 있던 근거 자체가 이미 사라진
상태였다 — 주석이 스스로 적어 두었다: *"셀프호스트 러너가 하나뿐이던 시절 ... hosted
러너로 옮기면서 그 굶주림은 없어졌다."* 남은 이유는 리듬뿐이었고, 러너가 여럿인 지금은
겹쳐 도는 비용이 이 구멍보다 싸다.

**나머지 둘은 안 건드린다.** `codeql.yml` 도 취소하지만 CodeQL 은 **트리를 재므로** 옛
주석의 주장이 그쪽에는 참이다. `nightly.yml` 은 `cancel-in-progress: false` 이고 목적이
다르다(야간 run 이 겹치지 않게).

## B. [Low] 동결 카운터가 세는 것은 「회차」가 아니라 「부른 횟수」였다

`--round` 는 표면이 안 움직였는지만 보고 카운터를 올렸다. 아무 근거도 요구하지 않았고
파일에도 아무것도 안 남겼다. **한 자리에서 세 번 부르면 동결 기준을 채운다.**

13차 검수가 준 기준은 *"여러 **적대적** 회차 동안 이 파일이 변하지 않을 것"* 이다.
그 회차가 무엇이었는지가 파일에 없으면 카운터는 그 기준을 재는 것이 아니다.

**`--unfreeze` 가 이미 반대쪽 규칙을 갖고 있었다** — 푸는 데는 근거가 필수이고 그 근거가
파일에 남는다. 그 문장이 이유까지 적어 뒀다: *"근거 없는 해제는 다음 사람이 「왜 풀렸지」
를 물을 때 답이 없다. 이 파일이 쌓아 온 회차 수는 그 답이 있을 때만 뜻이 있다."*
**푸는 데 근거가 필요하면 채우는 데도 필요하다.**

**고쳤다.** `--round "<근거>"` 가 필수고, 근거는 `# 회차 N: <근거>` 로 파일에 쌓인다.
`--unfreeze` 는 카운터와 함께 그 줄들도 지운다 — 카운터가 0 인데 근거만 남으면 파일이
두 가지를 동시에 말한다.

⚠️ **1·2 회차에는 그 줄이 없다.** 이 요구가 생기기 전에 올렸기 때문이다. 손으로 채우지
않는다(*"이 파일은 손으로 고치지 않는다"*) — 대신 그 둘이 무엇이었는지는
`docs/audit-2026-08-29.md`(PgSecretStore)와 `docs/audit-2026-08-29-install.md`
(`deploy/install.sh`)가 든다. **3 회차부터 파일이 스스로 답한다.**

## C. [안 고침] `--freeze-gate` 는 아무것도 안 부른다

`verify.sh --freeze-gate` 는 A 동결 선언과 B 드리프트를 함께 보는 모드인데
`verify.sh`(기본)도 어느 워크플로도 그것을 안 부른다.

**지금은 그것이 맞다** — A 가 미선언이라 켜면 항상 빨갛다. 그리고 실질 보호는 다른
데서 온다: `--check` 가 매 게이트에서 드리프트를 잡고, `--write` 는 동결된 기준을
**거부한다**(`--unfreeze` 로 근거를 남겨야 열린다).

남는 구멍은 좁다: 누가 `SURFACE.txt` 의 `A 동결: 선언` 을 손으로 `미선언` 으로 바꾸면
`--check` 는 그대로 통과한다. **선언을 선언 자체가 지키지는 않는다.**

### 결정 (2026-08-29, 사람)

**기본 게이트에 넣는다.** 다만 `--freeze-check` 를 그대로 걸 수는 없다 — 선언을 요구하므로
미선언 상태에서는 항상 빨갛고, 동결은 **선언하지 않기로 했다**(§4.3.1·§4.4 필드를 먼저
들인다. 그것들을 넣으면 표면이 움직여 카운터가 0 으로 간다).

그래서 `--freeze-status` 를 새로 낸다. 미선언 상태에서도 잴 것이 있다 — **카운터와 회차
근거가 맞물리는가.** 손으로 카운터만 올리면 마지막 `# 회차 N` 이 안 맞아 걸린다. 이 파일을
무력화하는 가장 싼 길이 그것이었고, *"손으로 고치지 않는다"* 는 규칙일 뿐 검사가 아니었다.

선언되면 회차 수와 표면 일치가 여기에 더해진다. **그래서 선언하는 날 이 자리를 다시 정할
일이 없다.**

## 잘 방어돼 있던 것 — 찾아갔다가 닫혀 있던 셋

정직하게 적어 둔다. 셋 다 구멍을 예상하고 갔다가 이미 막혀 있는 것을 봤다.

| 예상한 구멍 | 실제 |
|---|---|
| 조각으로 나누면서 **어느 조각에도 없는 단위**가 생긴다 | `run()` 이 `CURRENT_GROUP` 이 비면 즉시 FAIL — *"어느 조각에도 없다"* |
| **이름만 남고 빈 조각**이 초록으로 보인다 | `RAN -eq 0` 이면 FAIL — *"이름만 남고 내용이 없다"* |
| CI 매트릭스가 **빈 목록**이면 무거운 단계가 통째로 안 돈다 | `groups` 잡이 `test -n "$names"` 로 막는다 |

`group()` 이 `VERIFY_GROUPS` 에 없는 이름을 거절하는 것까지 넷이다. **나누기의 대표적
사고 넷이 전부 게이트로 옮겨져 있다.**
